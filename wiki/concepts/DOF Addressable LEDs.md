# DOF Addressable LEDs

Addressable LED strips and matrices (WS2811/WS2812/WS2815) in a [pincab](Pincab%20Setup.md) are driven by inexpensive dedicated microcontrollers that offload the LED bitstream from the main [DOF](../projects/DirectOutput%20Framework.md) controller. This page covers controller choice, wiring, firmware, configuration files, matrix setup, and troubleshooting.

> Source: community wiki (secondary). For the controller catalog context see [DOF Output Controllers](DOF%20Output%20Controllers.md); for effect/assignment logic see [DOF Toys and Effects](DOF%20Toys%20and%20Effects.md).

## Controller Tiers

([raw/ExternalWikis/dekay-vpinball-wiki/repo/AddressableLED.md](https://github.com/dekay/vpinball-wiki/wiki/AddressableLED), §Addressable LED Controllers)

| Board | Cost | Performance | Notes |
|-------|------|-------------|-------|
| **Wemos D1 Mini** | lowest | good; HD matrix animations may lag | ESP8266, pinout-compatible all versions (V4 = USB-C); 4 MB board suffices; up to 8 strips |
| **Wemos S2 Mini** | slightly more | higher | Preferred with D1-class firmware for HD matrices |
| **PJRC Teensy** | highest | highest | Teensy 3.1/3.2; preferred for HD LED matrices |

Preflashed units exist from PJRC, Cleveland Software Designs, and the Arnoz shop.

**Not all LED boards are addressable**: Cleveland PinOne, LED-Wiz, Pinscape Pico, and Dudes Cab/Moslight drive individual LEDs only — not addressable strings.

- ⚠️ CONFLICT (secondary source): the recommended Vroonsh TeensyStripController fork raises the per-line limit "from 1100 to 2100 LEDs" and is "likely to be merged into mainline"
  ([raw/ExternalWikis/dekay-vpinball-wiki/repo/AddressableLED.md](https://github.com/dekay/vpinball-wiki/wiki/AddressableLED), §PJRC Teensy) — Primary: [DOF Output Controllers](DOF%20Output%20Controllers.md) lists TeensyStripController at 8 channels × 1100 LEDs (mainline figure)

## Wiring and Firmware

- Wemos D1 strip outputs and DOF port mapping: D5→port 1, D6→4, D7→7, D8→10, D1→13, D2→16, D3→19, D4→22 — ports step by 3 (one per R,G,B channel per strip)
- **D0** is not an LED output — it is the test-button input for Arnoz PINMOS. **D4** shares the Wemos activity LED: the first strip LED blinks unless firmware disables it
- Firmware is open source (github Vroonsh/PincabLedStrip). With Arnoz Tiny Tools flash exactly `WemosD1MPLedstripController_ARNOZ_WS2812B_GRB.bin`
- **Color order**: Teensy firmware is compiled `RGB` internally; WS2812/13/15 strips are `GRB` — select `GRB` in the tool. WeMos firmware is compiled per chipset; keep firmware ↔ `cabinet.xml` ordering consistent
- Teensy forks: mainline DirectOutput/TeensyStripController; recommended Vroonsh fork (better timing, 2100 LEDs/line); Teensy LC uses the jsm174 fork

## Configuration Files

Four files, living with the rest of the DOF configuration ([raw/ExternalWikis/dekay-vpinball-wiki/repo/AddressableLED.md](https://github.com/dekay/vpinball-wiki/wiki/AddressableLED), §Configuration Files):

| File | Role |
|------|------|
| `tablemappings.xml` | Full table name → ROM name; regenerated by the DOF Config Tool |
| `directoutputconfig30.ini` | Per-table colors, macros, LED effects for WS2811-type controllers. Tables missing from it show no effects |
| `cabinet.xml` | Free-form name; output of the CSD Cabinet File Generator or Arnoz Tiny Tools Cacabinet Generator; must match `CabinetConfigFilePattern` in the GlobalConfig file |
| `GlobalConfig_B2SServer.xml` | Logging toggles + cabinet.xml pointer |

Matrices add `DirectOutputShapes.png` (animation sprite sheet + letter/number sets) and `DirectOutputShapes.xml` (its roadmap) — missing files mean missing or scrambled matrix images.

Per-device ini numbering: the WS2811 controller class uses `directoutputconfig30.ini`; each controller family has its own base number (Pinscape Pico = 120, LedWiz = base file, etc.) — see [Pinscape Pico](Pinscape%20Pico.md).

## Strips as Matrices

An LED strip is "a simplified LED matrix": mounted vertically beside the playfield it is one column wide, so `cabinet.xml` uses `Width=1`, `Height=<LED count>`, and a `<LedStripArrangement>` of `TopDown…`/`BottomUp…`. Getting the arrangement backwards breaks *some* effects only — a subtle, hard-to-trace failure ([raw/ExternalWikis/dekay-vpinball-wiki/repo/AddressableLED.md](https://github.com/dekay/vpinball-wiki/wiki/AddressableLED), §Configuration Files).

DOF Config Tool assignment uses **combo names**: e.g. `PF Left Combo` = `PF Left Effects MX` + `PF Left Flashers MX`; matrix: `PF Back Effects MX` + `PF Back Flashers MX` + `Custom MX 1`.

## HD vs SD Matrices

- **SD** = WS2812B "5050" (5.0 mm) LEDs, 8×8 / 8×16 grids; **HD** = "2020" (2.0 mm) LEDs, 16×16 / 16×32 grids, rigid PCB (16×32 panel = 80×160 mm); panels trimmable to width, usable piece is the Data-Input (left) side
- SD effects display fine on HD matrices — DOF scales bitmap regions to the matrix, resolution-independent; HD effects (VPCLE group) exploit the extra resolution
- **The `… MX HD` fields in the DOF Config Tool are effectively dead**: tables must be coded to call them and very few are; real HD support = custom DOF code in the regular `PF Back Effects MX` SD field. Exclude `PF Back Strobe MX` / `PF Back Beacon MX` from HD combos (they interfere). HD assets ship as `mx.rar` from the DOF home page — the Config Tool copies effect strings only, so mx.rar assets must be extracted into the config directory
- **Multi-panel wiring**: serial bitstreams slow down with LED count, so wire each panel's data-in to its own controller output; panels with the **same OutputName** merge into one logical matrix (CSD generator: `<LedWizEquivalentOutputNumber>` steps of 3; Arnoz generator: `Split` field per output, same toy name, same DofOutputPort; 4× 16×32 panels = 12 port assignments CSD-style or 3 Arnoz-style, same end result)
- Panels run at ~40% brightness; if HD blues/whites look bad, raise `<Brightness>` to ≥30 in cabinet.xml (image quality improves to ~30%)

## Table Script Gating

Tables coded `DOF 104, DOFPulse` fire unconditionally; tables using `Controller.vbs` variables depend on `[Controller]` values in `VPinballX.ini`: `DOFContactors`, `DOFKnocker`, `DOFChimes`, `DOFBell`, `DOFGear`, `DOFShaker`, `DOFFlippers`, `DOFTargets`, `DOFDropTargets` — **0 = digital sound only, 1 = DOF only, 2 = both**. `Controller.vbs` auto-adds these on first launch; VPX 10.8.1 (2026-02-15, commit 40dd999) automates this on all platforms; on Linux/Mac the placeholders may need filling manually. Plugin enable keys: 10.8.0 `[Standalone] B2SPlugins=1, DOFPlugin=1`; 10.8.1 `[Plugin.B2SLegacy] Enable=1`, `[Plugin.DOF] Enable=1`. Expect churn — the codebase is moving to a plugin architecture ([raw/ExternalWikis/dekay-vpinball-wiki/repo/AddressableLED.md](https://github.com/dekay/vpinball-wiki/wiki/AddressableLED), §Setting Up the VPinballX.ini File).

## Cross-Platform Serial Quirks

- **DOF is built into VPX Standalone 10.8.1 on Linux/Mac since late June 2025** — no separate plugin download
- `<ComPortName>` must be a `/dev` path (find via `sudo dmesg`, e.g. `/dev/ttyUSB0`); on Linux/Mac set `<ComPortDtrEnable>true</ComPortDtrEnable>` in `<WemosD1MPStripController>`
- udev rule required for USB permissions (symptom: `Could not connect to controller. Thread will quit…`); a self-built VPX includes the **`dof_test`** CLI — the S10 test (LEDs solid, then fade) verifies the chain
- **glibc 2.42 breaks libserialport** (check `ldd --version`); workaround `stty -F /dev/ttyUSB0 2000000`; fixed in glibc 2.43
- Windows `Could not put the controller on com-port … into the commandmode`: update the Wemos driver, disable **Modem Handshake** on the port; if persistent, disable motherboard RGB headers and **Windows Dynamic Lighting** (they can hijack the COM port)

## Troubleshooting Quick List

([raw/ExternalWikis/dekay-vpinball-wiki/repo/AddressableLED.md](https://github.com/dekay/vpinball-wiki/wiki/AddressableLED), §Troubleshooting)

| Symptom | Likely cause |
|---------|--------------|
| Controller unrecognized / disconnects | COM/device path, USB **data** cable, udev permissions, DTR/handshake settings, glibc 2.42 |
| Effects stop before strip end | Teensy-only Width/Height swap quirk — reverse the values |
| Effects on some tables only | `DOFContactors = 2` missing, or table absent from `directoutputconfig30.ini` |
| Wemos totally dead | Wrong Arnoz firmware bin flashed |
| Matrix images missing/scrambled | Missing `DirectOutputShapes.png/.xml`, or wrong `<LedStripArrangement>` |
